# WP-5.1 — `has_entity_name` and translation keys

Branch: `fix/wp-5.1-has-entity-name` (created from `integration/2.3+4.2`,
the integration line that already carries WP-3.4 (config flow rewrite,
entry v5) and WP-4.5 + the earlier phases. This repository has no
`master` branch — the plan's "cut from master" rule was read as "cut
from the available integration line" — so the base is the head of that
line at `ebdc80e`, which includes both prerequisite merges.)

## Scope, per the plan

- **CORE-26 (remainder)** — `_attr_has_entity_name = True` on all Loxone
  entities; delete the `functools.cached_property` overrides of `name` and
  `unique_id`; primary entities adopt the device name, sub-entities get
  short names. Adopted *with a release note* (the plan's Phase-5 decision),
  because it is a user-visible rename.
- **CORE-33 (partial convergence)** — the two entity idioms (explicit
  typed constructors + `_attr_*` vs kwargs-`setattr`) converge toward one:
  the base now assigns `_attr_name`/`_attr_unique_id` in one place, and the
  `self.name = ...` / `self.unique_id = ...` assignments in `switch.py`,
  `scene.py` and the `lights/` sub-control classes became `_attr_*`
  assignments. The full rewrite of the ~30 kwargs-style classes to explicit
  constructors is *not* in this package's file list; it is listed under
  Follow-ups.
- **CORE-22 (adjacent)** — the enum sensor's `translation_key`
  (`override_reason`) and the preset key on `LoxoneRoomControllerV2`
  (`room_controller_v2`) still exist; the shipped translation files were
  fixed so the paths are actually reachable (see below).

## What changed, by file

- `custom_components/loxone/__init__.py` — `LoxoneEntity`:
  `_attr_has_entity_name = True`; class-level `_attr_name = None`
  default (overridable per class, e.g. the Miniserver diagnostic
  sensors); `name`/`unique_id` `cached_property` overrides deleted; the
  constructor stores the raw control name in `self._lox_name` (still used
  by both `get_or_create_device` and `get_suggested_area`), assigns
  `_attr_unique_id` from `uuidAction`, and no longer overwrites
  `_attr_name` from the `name` kwarg.
- Every platform — device naming and classification read `self._lox_name`;
  entity display names per WP-5.1:
  - **primary** (one control = one device): no own name → adopts the
    device name, which is the control's own name (`LoxoneSwitch`,
    `LoxoneDimmer`, `LoxoneLightController`, `LoxoneRoomController{,V2}`,
    `LoxoneAcControl`, `LoxoneCover`, `LoxoneFan`, `LoxoneSensor`,
    `LoxoneDigitalSensor`, `LoxoneTilt`/`Jalousie`, `LoxoneNumber`,
    `LoxoneSlider`, `LoxoneButton`, `LoxoneAlarmControlPanel`,
    `LoxoneMediaPlayer`, `LoxoneTextSensor`, `LoxoneSceneSwitch`…).
  - **sub** (device owned by the parent control): short names only —
    `Comfort Override`, `Override Reason`, `Comfort Temperature`
    (+Cool), `Presence Detection`, meter registers
    `Actual`/`Total`/`Total Neg`/`Storage`, fan readings
    `Presence`/`Humidity`/`Air Quality`/`Temperature`, light sub-controls
    `Colour CT`/`Colour CT Full`/`Colour RGB`/`LCV2 Dimmer`/`LCV2 Switch`,
    scene inputs the mood name, the Intercom sub-mute takes the
    controller's name on the intercom device.
- `custom_components/loxone/{switch,scene}.py` + `lights/*.py` —
  `self.name = ...` / `self.unique_id = ...` → `_attr_*` (CORE-33);
  `LoxoneRoomControllerOverride` / `LoxoneLightPresenceSwitch` pass the
  short name instead of a parent-prefixed string.
- `custom_components/loxone/translations/{en,de,cs}.json` — the
  override-reason states moved from
  `entity.sensor.loxone.override_reason.state.<slug>` (unreachable by HA
  core's `component.{platform}.entity.{domain}.{translation_key}` lookup)
  to `entity.sensor.override_reason.state.<slug>`; the dead legacy
  `room_controller` preset block dropped from `en.json`; `room_controller_v2`
  preset states move one level up to the same core layout
  (`entity.climate.room_controller_v2.state_attributes.preset_mode.state`).
- **Snapshot artifacts** — new `tests/snapshots/entity_names.json`
  (post-change, generated by the new test) and
  `tests/snapshots/entity_names.pre.json` (pre-change baseline, generated
  from the unmodified base). **Reviewed diff** (all 39 loxone entities of
  the LoxAPP3 fixture):
  - `unique_id` — unchanged for all 39 entities;
  - `entity_id` — unchanged for all 39 entities (slugification of
    device-name + short name matches the old full-name slugs; verified
    against baseline, so upgrades re-name nothing and lose no id);
  - `has_entity_name` — `False` → `True` on all 39;
  - stored `original_name` — full-name primaries become `None` (adopt
    device name); sub-entities shorten
    (`…Override Reason` → `Override Reason`, `…Energy Meter Total` →
    `Total`, `…Living Light Controller-LCV2 Dimmer` → `LCV2 Dimmer`,
    `…Kitchen Ventilation - Presence` → `Presence`, …);
  - device names/models — unchanged.
- `tests/` (part of the WP):
  - **new** `tests/test_entity_name_snapshot.py` (12 tests, all RED
    before the change, all green after): registry snapshot compared
    against the committed, hand-reviewed file (device_id excluded — it
    is a random per-run uuid); no "Device Device" overlap in the
    snapshot; `has_entity_name` on every loxone entry; name-state tests
    for primary switch/sensor and override/presence/dimmer sub-entities;
    translation-key layout (en renders `window_open` → "Window Open";
    the old dead path must be gone). The snapshot test self-generates
    when `LOXONE_ENTITY_SNAPSHOT_OUT=…` is set.
  - Adjusted to the new naming (fixture-driven tests that had pinned the
    old long names): `tests/test_simple_platforms.py` (presence switch,
    override-reason translation path), `tests/test_lights.py` (LCV2 sub
    picker short name), `tests/test_climate.py` (legacy RGC asserts
    device name + empty entity name instead of full "Foyer Climate").
- `CHANGELOG.md` — release note under *Unreleased* (the plan requires a
  release note for the user-visible rename).
